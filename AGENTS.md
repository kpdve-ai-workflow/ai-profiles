# Repository guide

- Python 3.10+; runtime and tests use only the standard library. Core entrypoints are `profile.py` (profile management/validation) and `mcp_runtime.py` (local MCP overrides and stdio adapter); `ai-profile` is a thin CLI wrapper.
- Verify source/profile changes with `make validate` and `make test` (equivalent test command: `python3 -m unittest discover -s tests -v`). Tests copy the repo into temporary directories and exercise project installation there; do not test against a real project.
- Profiles are discovered from `profiles/<name>/`; keep `profile.json`'s `name` equal to the directory. Each profile's `mcp.json` selects central `mcp/servers/<name>.json` definitions via `{"servers": ["name"]}`; registry entries are never installed implicitly. The manager combines these selections and common/profile skills into generated project files. `make validate` checks the registry and profiles, including that selected definitions collectively match `mcp/example.json`. Bump only consuming profiles when changing a registry definition.
- Put shared skills in `common/skills/` and profile-specific skills in `profiles/<name>/skills/<skill>/`. Shared changes affect every profile; bump each affected profile deliberately with `make bump PROFILE=<name> PART=patch|minor|major` (versions are independent and are not bumped automatically).
- Optional MCP launcher assets live in `mcp/launchers/<name>/` and are copied to `.opencode/mcp/<name>/` only for selecting profiles. Keep runtime build/cache data and secrets outside managed source files. MariaDB's launcher builds pinned upstream sources on first enabled start, not during profile installation; tests must mock Docker/downloads or use temporary copies, never a real project's database.
- User-facing profile tools live in `profiles/<name>/scripts/` and install to `.opencode/ai-profile/scripts/`, never inside skills. Installing/updating a profile must not execute them. WordPress's Updraft restore defaults to a read-only plan; database replacement requires `--apply`, project-name confirmation and a verified local backup. Test with fake DDEV/WP-CLI, not a real site's database.
- `README.md` documents the project-facing install/update workflow, local MCP overrides, and safety/ownership behavior. In particular, project `.opencode/ai-profile.local.json` is user-owned; do not replace it with generated profile configuration. Avoid editing generated entries in a project's `opencode.json` by hand.
