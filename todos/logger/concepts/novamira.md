# Novamira diagnostics

**Roadmap coverage:** NOVAMIRA-WRAPPER and NOVAMIRA-UPSTREAM. **Source:** [Novamira visibility requirements](../logger.md#novamira-i-granice-obserwowalności). Requirements: REQ-DATA, REQ-CORRELATION, REQ-SEMANTICS, REQ-HEALTH, REQ-BOUNDARIES.

## Wrapper diagnostics

Primary code: [mcp/novamira.rs](../../../core/src/mcp/novamira.rs), `configuration_failure`, `run`, message reading/forwarding and `Bridge` cleanup; [mcp/runtime.rs](../../../core/src/mcp/runtime.rs), the branch entering the guard.

Record configuration rejection, actual initialization/protocol messages seen or generated by the guard, internal diagnostic requests, error classification inputs, forwarding/parse failures, observed closure and cleanup outcomes. Capture operation-related raw bytes in payloads, not only a sanitized authentication summary. Correlate the internal tools/list request distinctly from client-originated traffic.

Keep actual MCP response/forwarding semantics and raw diagnostic storage separate. Do not leak diagnostic records into MCP stdout or replace the currently defined client-facing error with raw bridge text. Storage is unmasked; that does not require modifying protocol messages. Do not claim a raw HTTP request was observed solely from a parsed MCP error.

Extend [novamira.rs tests](../../../core/tests/novamira.rs) using controlled synthetic bridge messages. Oracles: exact fixture protocol bytes, the initialize contract, and the confirmed-status rule for HTTP 401 classification. Verify error and successful flows, raw byte capture, correlation, and unchanged protocol/cleanup. Existing real-bridge tests remain necessary for claims about actual bridge behavior.

## Bridge and HTTP diagnostics

This responsibility closes visibility inside the actual pinned bridge/container: available request/response content, raw diagnostics and concrete failure causes, recorded locally through a channel separate from MCP stdout.

Before implementation, resolve [NOVAMIRA-CHANNEL](../decisions-and-gaps.md#novamira-diagnostic-channel). Inspect the actual pinned deployment files and artifact interfaces; the current wrapper is not evidence of a complete bridge HTTP channel. Do not enable upstream logging without a collector/routing contract and call that complete.

Acceptance requires the real pinned bridge/container against a controlled HTTP fixture, with independently known request/response bytes and errors. Verify full capture, locality, correlation, absence of protocol contamination and correct cleanup under failure. Synthetic wrapper mocks cannot establish this integration. Follow [quality rules](../quality-and-acceptance.md) and select gates from actual changed components; do not assume every Docker change is a Playwright image change.

No host Node/npm dependency, external telemetry sink, upstream version replacement, or client protocol redesign is authorized by the existence of this task.
